# Testing

Panelingo has three layers of automated tests plus a manual checklist for real sites. Run `npm run check` after
every change and `npm run check:full` before you open a pull request that touches runtime code.

| When                  | Command                                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------- |
| After every change    | `npm run check` (typecheck, lint, format, unit + integration with coverage)                                         |
| Before a pull request | `npm run check:full` (`check` + E2E in a real Chrome)                                                               |
| Before a release      | `npm run check:full` on a machine with a GPU, plus [manual-checklist.md](manual-checklist.md) on a few real readers |

> **Golden rule: tests never call a real AI provider or a real comic site.** They use the mock OpenAI-compatible
> server, a fake `fetch`, or the local fixture server on ephemeral ports. `test/support/setup.ts` installs a guard on
> the global `fetch` that refuses a reserved loopback port and fails the test file, even if the code under test
> swallows the error.

## Test data

Most tests use **synthetic** comic pages generated by `tools/fixtures/` (Python + Pillow). Every image is original:
abstract panel art, with lettering set from sentences written for this project
(`test/fixtures/sentences/*.json`). Each image comes with a ground-truth file (`<name>.gt.json`) that holds exact ink
boxes, bubbles, reading order and the expected lines.

```sh
npm run fixtures   # about 800 files, 72 MB, about 25 s, into test/fixtures/generated/ (gitignored)
```

- The output is deterministic: the same seed and environment produce byte-identical files.
- The generator reads Windows fonts (Malgun Gothic, Yu Gothic, Microsoft YaHei, Comic Sans MS, Impact, Arial) from
  `C:/Windows/Fonts`. Use `--font-dir` to point it elsewhere. It never copies fonts into the repository.
- `--lite` skips the 200-slice soak chapter. Some decode tests need that chapter, so use the full run for `npm test`.
- Several unit and integration tests read `test/fixtures/generated/`, so generate it once after cloning. CI generates
  it on a Windows runner and passes it to the Linux test job as an artifact (see `.github/workflows/ci.yml`).
- `npm run test:fixtures` runs the generator's own Python tests. They skip when the fonts are missing.

Committed fixtures:

| Path                       | Contents                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------- |
| `assets/canary/`           | The detector canary page and its WebAssembly reference output, shipped with the extension.   |
| `test/fixtures/sse/`       | Recorded server-sent-event transcripts, byte-exact (CRLF vs LF matters), for the SSE parser. |
| `test/fixtures/sites/`     | Fixture reader pages (paged, webtoon, seam, srcset, protected, SPA, canvas, CSP, iframe, …). |
| `test/fixtures/sentences/` | Source sentences per language for the generator.                                             |

## Unit tests

- **Runner.** Node's built-in `node:test` with `--import ./test/support/setup.ts`. No bundler, no Jest. TypeScript runs
  directly through Node's type stripping.
- **Layout.** `test/unit/` mirrors `src/`: `content/`, `core/`, `engine/`, `platform/`, `shared/`, `sw/`, `ui/`,
  plus `scripts/`, `tools/` and `support/`.
- **Coverage.** `npm run test:cov` enforces ≥ 85% line coverage on `src/shared/**`, where the pure algorithms live.
- **Pure code first.** Most logic lives in `src/shared/core/` and is tested without any fake: slicing, detection
  post-processing, reading order, erasing, packing, composite layout, prompt, SSE and line parsing, id accounting, retry
  policy and text fitting. Text fitting takes an injected `measure` function. Erase and composite tests run on real
  pixels through the Node graphics port.
- **Graphics in Node.** `tools/gfx-node.ts` implements the extension's graphics port with
  [`@napi-rs/canvas`](https://github.com/Brooooooklyn/canvas). Compare geometry or pixels with a tolerance, never
  encoded bytes, because encoders differ between platforms.
- **IndexedDB.** Store tests use [`fake-indexeddb`](https://github.com/dumbmatter/fakeIndexedDB).

### Build-time constants

`test/support/setup.ts` defines `__BUILD_ID__`, `__DEV__` and `__TEST__` before any test module loads. Production
code uses these bare identifiers, so esbuild can strip test-only code from dev and prod bundles.

### The Chrome fake

`test/support/chrome-fake.ts` provides a `FakeBrowser` that simulates Chrome for one extension:

- **Contexts.** Each context has its own `chrome` namespace: service worker, offscreen engine, popup, side panel,
  options, debug page, and one content script per tab and frame. Storage, DNR rules, registered scripts, menus,
  badges and alarms are shared, as in Chrome.
- **Running code.** `browser.install()` points `globalThis.chrome` at the current context through
  `AsyncLocalStorage`. Run code inside a context with `ctx.run(fn)` or `browser.run(ctx, fn)`. Call
  `await browser.settle()` to wait until every message and port event has been delivered.
- **Realistic delivery.**
  - Messages are delivered asynchronously and payloads are cloned.
  - With `strictWire`, payloads that are not wire-safe are rejected (protocol rule R6).
  - Errors use Chrome's exact strings (`CHROME_ERRORS`).
  - JSON and structured-clone serialization can both be simulated.
- **Fault injection and lifecycle.**
  - `failNext(api, error, times)` makes the next calls to an API fail.
  - `restartServiceWorker()`, `invalidateExtension()` (orphaned content scripts), a single offscreen document, the
    `captureVisibleTab` quota (2 per second) and the user-gesture requirement of `sidePanel.open`.
  - Tabs and frames: `openTab`, `addFrame`, `injectContent`, `navigate`, `closeTab`.
  - Events: `fireInstalled`, `fireStartup`, `fireCommand`, `clickMenu`, `clickAction`.

The fake has its own tests in `test/unit/support/chrome-fake.test.ts`.

## Integration tests

`test/integration/` exercises several modules together, in-process and on ephemeral ports:

| Test                     | Covers                                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `translator.test.ts`     | The engine's translator end to end against the mock server in oracle mode: composite → request → stream → parse → ids. |
| `mock-*.test.ts`         | The mock server itself: wire format, scenarios, oracle answers, latency profiles.                                      |
| `fixture-server.test.ts` | The fixture server: Referer and cookie gates, CDN knobs, redirects, request log, path safety (on a temporary tree).    |
| `gfx-node.test.ts`       | The graphics pipeline in Node: strips → layout → render → JPEG → decode.                                               |

## End-to-end tests

```sh
npm run test:e2e        # build:test, then node --test e2e/**/*.e2e.ts (serial, 180 s per test), headless
npm run test:e2e:gpu    # build:test, then the same files headed (e2e/run-gpu.ts sets CTV_HEADED=1)
node --test --test-concurrency=1 --test-timeout=180000 e2e/errors.e2e.ts   # one file, after build:test
```

- **Browser.** E2E uses [`puppeteer-core`](https://pptr.dev/) with `pipe: true` and `enableExtensions`. Chrome loads
  the unpacked test build through the DevTools protocol, because branded Chrome has ignored `--load-extension` since
  version 137. It runs headless by default; headed runs (`test:e2e:gpu`) get real WebGPU and `captureVisibleTab`.
- **Which Chrome.** By default the tests use the platform's Chrome Stable path. Set `CHROME_PATH` to use another binary.
  If a future Chrome blocks this way of loading extensions, install Chrome for Testing
  (`npx @puppeteer/browsers install chrome@stable --path .cache/browsers`) and point `CHROME_PATH` at it.
- **Harness.** Every file launches its own Chrome profile in `before()` and closes it in `after()`
  (`e2e/helpers/launch.ts`): the fixture server and the mock server start in-process on ephemeral ports, and the
  settings are seeded with endpoint = mock, the fixture hosts and the privacy notice accepted. Test builds send an
  oracle header (`x-ctv-test-units`), so the mock answers from the fixtures' ground truth, and they write a summary of
  the content script to `document.documentElement.dataset.ctvTest` (`src/content/test-hooks.ts`). Tests within a file
  run in order and may build on each other (one profile, one translation cache).
- **Coverage targets.** Balloon units (dialogue, thought, narration) must be painted at ≥ 95%; free text (signs,
  sound effects) depends more on the detector's recall on synthetic lettering and is not held to that bar. Painted
  units are matched to ground truth by their text (the oracle answers with the fixture's expected line).

  IndexedDB log when a test fails. Change settings with `h.patchSettings()` (deep merge): `h.setStorage({settings})`

- **CI.** The `e2e` job in `.github/workflows/ci.yml` runs `npm run test:e2e` on `ubuntu-latest` with the generated

- **Environment variables.**

  | Variable            | Effect                                                                 |
  | ------------------- | ---------------------------------------------------------------------- |
  | `CHROME_PATH`       | Chrome executable to launch.                                           |

- **Debugging.** `node e2e/debug-run.ts [set]` (after `npm run build:test`) runs `/paged/?set=<set>` against the mock
  and prints the content summary, the painted units (erase kind, font size, plate color), the mock's requests and the
  engine log. Add `CTV_HEADED=1` to watch it, `CTV_SETTLE_MS=<ms>` to wait before reading the overlay and
  `CTV_SHOT=<file.png>` for a full-page screenshot. `node e2e/popup-shot.ts <out.png>` screenshots the popup; `node e2e/options-shot.ts <out.png> [locale] [light|dark]` takes a full-page screenshot of the options page with a site editor and the Advanced section open; `node e2e/sidepanel-shot.ts <dir>` saves the side panel's Transcript and Glossary views; `node e2e/docs-shots.ts` regenerates the README and store images in `docs/images` (see `docs/images/README.md`). A failing
  test prints the same diagnostics by itself; rerun a single test with `--test-name-pattern="<part of its name>"`.

## Mock server and fixture server

| Tool           | Command                  | Default address                                             | Purpose                                                                                    |
| -------------- | ------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Mock API       | `npm run mock-api`       | `http://127.0.0.1:4925`                                     | `GET /v1/models`, streaming `POST /v1/chat/completions`, scenarios, oracle answers.        |
| Fixture server | `npm run serve:fixtures` | reader `http://127.0.0.1:8080`, CDN `http://localhost:8081` | Two origins, so images are cross-site as on real readers. Referer/cookie gates and delays. |

**Mock scenarios** can be set per server (`--scenario`), per request (`?scenario=`) or at runtime
(`POST /__scenario`). They cover:

- first-byte and inter-chunk delays, chunking, CRLF or LF line endings;
- failures before headers (HTTP errors, timeouts) and streams dropped after N chunks;
- missing, duplicate, unknown or garbage ids;
- refusals, empty answers and replays of recorded transcripts.

`GET /__requests` returns what the extension sent, and `/__reset` clears the state.

**Oracle header.** Test builds send `x-ctv-test-units`: base64 of UTF-8 JSON `[{ n, src, box: { x1, y1, x2, y2 } }]`.
Boxes are in natural pixels, and `src` is the image path relative to `test/fixtures/generated`. With it, the mock
answers with the ground-truth lines for each numbered region.

**Fixture CDN routes** include `/img/<path>`, `/protected/<path>` (403 without a reader Referer), `/protected-full/<path>`
(403 without a full page URL), `/protected-cookie/<path>`, `/redirect?to=` (SSRF-guard tests) and `/__log`. Query
knobs: `delay`, `status`, `cors`, `cache`. See `tools/fixture-server/README.md` for the full list.

## Writing tests

- Put pure logic in `src/shared/core/` and test it there first. It is the cheapest place to test and it counts toward
  coverage.
- Engine, service-worker and content-script code gets its dependencies (clock, fetch, storage, graphics) injected. Use
  the Chrome fake or small hand-written fakes, not network calls.
- Never call a real provider. To reproduce a provider's behavior, record its SSE output into `test/fixtures/sse/`
  (strip keys and personal data) or add a mock scenario.
- Never commit copyrighted comic pages. Use or extend the synthetic fixtures.
- Timing-sensitive code takes an injected clock. In test builds, minute-based engine settings run 60× faster.
- Visual changes to erasing or lettering: also check the result by eye on the fixture pages and on a real reader. Put
  before/after screenshots in the pull request.

## Manual testing

Automated tests cannot cover every real reader. Before a release, run through
[manual-checklist.md](manual-checklist.md) on a few sites you read.

Service-worker lifetime and timer-throttling behavior must be checked in a normal Chrome profile **with DevTools
closed**. Open DevTools cancels the service worker's idle shutdown, and Puppeteer disables throttling by default.
